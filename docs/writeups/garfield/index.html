Garfield

Logon scripts, delegated AD permissions, and the trust boundary around a read-only domain controller.

Dylan Senez · d4rkgunn3r · Working notes

Working draft — not ready for HTB submission

Adapted from my existing lab notes. The recorded chain reaches Administrator, but missing scripts, triggers, and evidence prevent a complete reproduction. No missing execution steps have been invented.

01 / Overview

The source notes record an assume-breach assessment of garfield.htb. Starting with a domain account, the recorded path moves through a writable logon script configuration, l.wilson_adm, membership in RODC Administrators, changes to the RODC password replication policy, and privileged secrets replication.

Domain user → Logon script → Administrative account → RODC control → Domain Administrator

02 / Enumeration

The scan identifies DC01 with DNS, Kerberos, LDAP, SMB, RDP, and WinRM exposed. The commands below are retained from the notes; credentials are represented as variables.

nmap -sVC -p- 10.129.17.121 -T3 --min-rate 5000
smbmap -H garfield.htb -u 'j.arbuckle' -p "$LAB_PASSWORD"

Initial share enumeration records read access to SYSVOL and NETLOGON. Read permission at the share level does not resolve effective write permissions on every child directory; the later script upload needs its own evidence. The scan also records required SMB signing and substantial clock skew. Required signing is a defensive control, not a vulnerability.

03 / Logon script path

The timeline records uploading printerDetect.bat to the SYSVOL scripts directory and setting l.wilson's scriptPath to that filename. It subsequently records authentication as l.wilson_adm over WinRM.

The exact batch file, execution trigger, and transition from l.wilson to l.wilson_adm are absent from the current document. These are reproduction gaps rather than verified instructions for the reader.

04 / RODC permissions

The notes record that Tier 1 has Self-Membership rights over RODC Administrators. They then record adding l.wilson_adm to that group, identifying writable attributes on the RODC01 computer object, and resetting the RODC01$ machine account password.

Preserving the exact DACL output matters here: group membership alone does not establish which operation is permitted on a computer object.

05 / Replication policy

The recorded sequence changes msDS-RevealOnDemandGroup to include Domain Admins and clears msDS-NeverRevealGroup. It then uses a custom script to request EXOP_REPL_SECRETS and records recovery of privileged account hashes, followed by Administrator WinRM access.

The current document names modify_rodc_policy.py and rodc_expo.py but does not include their source, dependencies, arguments, or complete output. Internal RODC connectivity and the replication details still require validation against the original session artifacts.

06 / Reproduction gaps

  • Restore the exact logon script, upload command, and execution trigger.
  • Explain and evidence the transition to l.wilson_adm.
  • Include both custom Python scripts and their dependencies.
  • Document RODC addressing, connectivity, and any pivot.
  • Attach trimmed command output proving each permission and transition.
  • Reconcile changing target IPs across sessions and replace proof placeholders.

07 / Defensive perspective

Review delegated write access to user logon script attributes and SYSVOL script directories. Audit group membership rights and RODC computer object permissions. Monitor unexpected machine password resets and changes to RODC password replication policy.

These are defensive implications of the recorded path. They are not claims that detections were deployed or tested during this lab.
